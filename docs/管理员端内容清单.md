# 管理员端 · 全量内容清单（用于交给 AI 重新设计导航与主看板）

> 用途：把这份文档整份投喂给另一个 AI，即可让它生成「炫酷动态导航栏 + 可视化主看板」。
> 本文档只描述**现有系统真实存在的内容与数据结构**，不含臆造。
> 数据核对时间：2026-11-04，取自运行中的系统（`http://127.0.0.1:8082`）。

---

## 0. 给 AI 的任务说明（可直接复制给下一个 AI）

> 你是资深数据可视化 + 前端动效工程师。下面是一个教育 SaaS「智课共生」管理端的完整内容清单。
> 请基于它设计：① 一套**有动态感的侧边导航**（悬停/选中态有位移或光效，克制不花哨）；② 一个**新的数据主看板**（KPI 卡 + 趋势 + 分布 + TOP 榜）。
> 约束：使用 Vue3 + TypeScript + Element Plus + ECharts；主色 `#2563eb`；动效时长 160/240/320ms，缓动 `cubic-bezier(0.4,0,0.2,1)`；所有动效只动 `transform` / `opacity`；必须支持 `prefers-reduced-motion`。
> 不要改变现有路由路径与接口契约（见第 4、5 节），只替换视觉层。

## 1. 系统定位与信息架构

管理端有**两个入口**，是同一套后台的两种外壳：

| 入口 | 地址 | 技术 | 说明 |
|---|---|---|---|
| SPA 管理端（主，推荐以此为准） | `/admin/login` → `/admin/dashboard` | Vue3 + Element Plus | 14 个功能页，数据来自学生/管理服务（JSON API） |
| 多页管理端（旧） | `/admin/login.html` → `/admin/home.html` | 原生 HTML + app.js | 5 个运维页，数据来自宿主服务（`/admin-api/*`） |

**重新设计请以 SPA 管理端为基准**；多页端保留不做视觉改造（第 6 节列出其内容，供你判断是否合并）。

管理端三层职责：
1. **看数据**：平台活跃、学习时长、问答量、生成量、异常趋势
2. **管内容**：资源审核发布、生成内容治理、文档审核、内容安全
3. **管人与配置**：用户/管理员账号、菜单权限、画像维度、学习路径、智能体、系统参数

## 4. 主看板（数据大盘）—— 重设计的重点

### 4.1 现有结构

1. Hero 色带：标题「数据大盘」+ 说明「掌握平台活跃、学习时长与问答趋势，辅助运营决策。」
2. **5 张 KPI 卡**（横向一行，每张：大数字 + 标签 + 专属色）
3. **平台趋势**（折线，2/3 宽，7天/30天切换）
4. **功能使用占比**（环形饼图，1/3 宽）
5. **热门知识点 TOP10**（表格：排名 / 知识点 / 提问次数）

### 4.2 KPI 卡（字段与配色，可直接复用）

| 标签 | 字段 | 当前值 | 主色 |
|---|---|---|---|
| 总用户数 | `total_users` | 11 | `#2563eb`（蓝） |
| 日活用户 | `dau_users` | 2 | `#10b981`（绿） |
| 累计学习时长(h) | `total_study_hours` | 0.0 | `#f59e0b`（琥珀） |
| 问答总量 | `qa_total` | 4 | `#8b5cf6`（紫） |
| 多模态生成 | `multimodal_total` | 6 | `#ec4899`（粉） |

### 4.3 图表数据契约

```ts
// GET /api/v1/admin/analytics/overview
{ total_users: number; dau_users: number; total_study_hours: number; qa_total: number; multimodal_total: number }

// GET /api/v1/admin/analytics/trends?days=7|30
{ days: number; dates: string[]; registrations: number[]; qa_counts: number[]; lecture_counts: number[] }
// 示例（7 天）：dates ["2026-10-29", ...]；registrations [0,0,0,...]；qa_counts [0,1,0,...]；lecture_counts [0,0,0,...]

// GET /api/v1/admin/analytics/feature-usage
[{ name: "纯文字问答", value: 10 }, { name: "视频讲解", value: 6 }]

// GET /api/v1/admin/analytics/top-topics
[{ topic: "高等数学", count: 1 }, { topic: "逻辑回归", count: 1 }, ...]   // 按 count 降序，取前 10
```

趋势图三条线语义：**用户注册**（registrations）、**问答量**（qa_counts）、**视频讲解**（lecture_counts）。

### 4.4 可增强的可视化方向（给 AI 的自由度）

- KPI 卡：数字滚动、迷你 sparkline、环比角标（注意：无数据时必须显示「暂无」，**不允许编造环比**）
- 趋势：双轴（人数 vs 次数）或面积堆叠，7/30 天分段切换带过渡动画
- 分布：环形图 + 中心总量 + 图例百分比
- TOP 榜：条形进度 + 排名徽章，或做成滚动榜单
- 可选新增（数据都拿得到）：异常数、待审核资源数、待审文档数、智能体任务量——见各页统计口径

## 5. 逐页内容清单（14 页）

> 格式：**路由 → 页面标题 / Hero 说明 → 区块与字段 → 操作 → 接口**
> 表格列即页面可见列，可直接用于重设计时的信息密度参考。

### 5.1 用户管理 `/admin/users`
- Hero：学生用户管理 —— 「查看学员账号状态、学习概况，并支持检索与运维操作。」
- 顶部统计：正常 / 禁用（两个状态计数）
- 筛选：关键词搜索、状态
- 表格列：ID、账号、姓名、专业、画像完整度、注册时间、最后登录、状态、操作
- 操作：批量启用、批量禁用、搜索、详情（跳 `/admin/users/:id`）
- 接口：`GET /api/v1/admin/users`、`PUT /api/v1/admin/users/{id}/status`

### 5.2 用户详情 `/admin/users/:id`
- 区块：基础信息（用户名/昵称/真实姓名/学号/专业/年级/邮箱/手机/状态/注册时间/最后登录/登录IP）、学习数据概览（画像完整度、答疑会话数）
- 操作：返回列表、保存、取消

### 5.3 管理员账号 `/admin/admins`
- Hero：「维护后台权限账号与角色，保障管理端访问可控。」
- 表格列：ID、账号、姓名、角色、最后登录、状态、操作
- 弹窗表单：账号、密码、昵称、真实姓名、角色（super 超级 / ops 运维 / content 内容）、状态
- 操作：搜索、配置/保存、取消
- 接口：`/api/v1/admin/users`（筛选管理员）、`PUT /api/v1/admin/users/{id}`

### 5.4 菜单配置 `/admin/menus`
- Hero：「编排侧栏结构与权限入口，让后台导航与职责对齐。」
- 表格列：排序、菜单名称、路由路径、权限码、图标、操作
- 弹窗：权限码、菜单名称、排序
- 操作：保存、取消
- 接口：`GET /api/v1/admin/menus`、`PUT /api/v1/admin/menus/{code}`

### 5.5 资源管理 `/admin/resources`
- Hero：「审核、发布与下架讲义、习题、图谱与视频等学习内容。」
- 顶部统计：待审核 / 已发布 / 已拒绝
- 筛选：类型、状态、关键词
- 表格列：ID、标题、类型、用户、主题、状态、操作
- 操作：查看内容、发布、下架、删除、批量发布、批量下架、导出 JSON
- 接口：`GET /api/v1/admin/content/resources`、`PUT /api/v1/admin/resources/{id}/status`、`POST /api/v1/admin/resources/batch-status`、`DELETE /api/v1/admin/resources/{id}`、`GET /api/v1/admin/resources/export`
- 状态枚举：`0`生成中 `1`待审核 `2`已发布 `3`已拒绝

### 5.6 画像配置 `/admin/profile-config`
- Hero：「配置六维画像维度与采集规则，支撑个性化学习诊断。」
- 区块一 **画像维度**：排序、编码、名称、问题指引、状态、操作
- 区块二 **标签库**：编码、名称、分类、操作
- 操作：新增标签、编辑、禁用、保存、取消、删除
- 接口：`GET/POST/PUT/DELETE /api/v1/admin/profile/dimensions`、标签相关同上

### 5.7 学习路径 `/admin/learning-paths`
- Hero：「维护知识图谱路径与节点，组织循序渐进的学习路线。」
- 区块一 **用户学习路径**：ID、路径标题、用户、节点数、目标、操作
- 区块二 **知识点库**：编码、名称、领域、难度、预估分钟、操作
- 操作：新增知识点、编辑、禁用、详情、保存、取消
- 接口：`/api/v1/admin/paths`、`/api/v1/admin/paths/nodes`

### 5.8 生成内容 `/admin/generated-content`
- Hero：「管理智能答疑与多模态产出，追溯生成记录与质量。」
- 区块一 **视频讲解**：标题、用户、幻灯片、主题、操作（查看视频 / 删除）
- 区块二 **知识点图像**：标题、用户、说明、操作
- 操作：搜索、查看视频、删除
- 接口：`/api/v1/admin/content/generated`、`/api/v1/admin/content/generated/{id}`

### 5.9 文档审核 `/admin/documents`
- Hero：「审核学员上传材料，控制可见范围与引用合规性。」
- 顶部统计：待审核 / 已通过 / 已驳回
- 表格列：文件名、用户、页数、大小、审核、操作
- 操作：查看文档、通过、批量通过、批量驳回、批量删除、审核配置（开关/单文件上限MB/允许格式）、保存
- 接口：`/api/v1/admin/documents`、`/api/v1/admin/documents/{id}/audit`、`/api/v1/admin/documents/settings`

### 5.10 内容安全 `/admin/content-audit`
- Hero：「敏感词过滤、事实校验与全链路调用追溯一体化管理。」
- 顶部统计：审核记录 / 拒绝 / 通过 / 待复核
- 表格列：ID、类型、对象ID、内容快照、结果、风险、时间、操作（复核 / 通过 / 重试 / 下架）
- 二次区块 **LLM 调用追溯**：ID、模型、耗时、Token、状态、时间
- 操作：刷新、复核、通过、重试、下架
- 接口：`/api/v1/admin/content/audits`、`/api/v1/admin/content/audits/{id}/review`、`/api/v1/admin/security/llm-calls`

### 5.11 智能体配置 `/admin/agents`
- Hero：「查看多智能体定义与协作编排，保障生成链路可运营。」
- 表格列：编码、名称、类型、默认模型、描述、状态、操作（配置）
- 弹窗：Agent 编码（只读）、Agent 名称、描述、默认模型（spark-pro / spark-ultra / deepseek-coder / qwen-plus / mock-v1）、Prompt 模板（留空不改）、启用状态
- 接口：`GET /api/v1/agents/definitions`、`PUT /api/v1/agents/definitions/{code}`
- 现网 14 个智能体（编码示例）：orchestrator、learning_analysis、document、question、mindmap、extension、animation、consistency 等

### 5.12 系统设置 `/admin/settings`
- Hero：「配置 LLM、安全策略、公告与反馈等平台运行参数。」
- 5 个页签：
  1. **LLM 与参数**：默认/备用提供商、内容安全审核开关、画像完整度阈值、接口限流(次/分)、答疑最大 Token、流式超时(秒)、通义千问 Key、DeepSeek Key、讯飞星火 Key/Secret、Serper Key —— 保存参数
  2. **功能开关**：联网搜索、深度模式、图像生成、视频讲解、语音输入 —— 保存开关
  3. **站点信息**：站点名称、Logo URL、ICP 备案号、页脚文案 —— 保存站点信息
  4. **公告管理**：公告列表（标题/内容/状态/优先级/发布时间）+ 新增/编辑/删除
  5. **反馈工单**：用户反馈列表（用户/内容/状态/时间）+ 处理回复
- 接口：`GET/PUT /api/v1/admin/settings/system`、`/api/v1/admin/announcements`、`/api/v1/admin/feedback`

### 5.13 操作日志 `/admin/operation-logs`
- Hero：「追溯管理员关键操作，满足审计与问题定位需求。」
- 顶部统计：成功 / 失败
- 筛选：关键词、模块、结果
- 表格列：ID、用户、模块、方法、请求路径、状态码、耗时、结果、IP、时间
- 操作：搜索
- 接口：`GET /api/v1/admin/security/logs`

### 5.14 异常监控 `/admin/exception-monitor`
- Hero：「跟踪接口异常与趋势，及时发现并清理过期故障记录。」
- 顶部统计：未处理 / 已处理
- 区块一 **异常趋势**（按日折线/柱状）
- 区块二 **异常记录**：类型、错误信息、路径、用户、状态、时间、操作（标记处理 / 重新打开）
- 操作：清理过期日志
- 接口：`GET /api/v1/admin/security/exceptions`、`PUT /api/v1/admin/security/exceptions/{id}`、`DELETE /api/v1/admin/security/exceptions/expired`

## 7. 全局交互与状态（重设计时不要丢掉）

- **空态**：表格 `empty-text`、卡片空态、图表无数据时的「暂无数据」
- **加载**：表格 `v-loading`、首屏骨架（现有页面多为 loading 遮罩）
- **失败态**：请求失败 `ElMessage.error`，页面保留骨架不白屏
- **确认**：删除/下架/禁用走 `ElMessageBox.confirm`
- **权限**：按 `adminLevel` 隐藏入口，无权限跳 `/admin/forbidden`
- **诚实原则（重要）**：无数据显示「暂无」，**禁止**用 0 或编造数据填充；演示数据必须可追溯到真实接口

## 10. 重设计时需要避开的坑

1. **不要伪造数据**：接口没数据就显示「暂无」，这是项目的验收原则之一。
2. **不要改路由与接口**：`/admin/*` 路径与 `adminOps` API 已被权限码、菜单配置与后端绑定。
3. **菜单来自后端**：`GET /api/v1/admin/menus` 动态下发，难度在于新导航要能吃这个结构（`title/path/icon/sort/perm_code`），不要写死。
4. **图标是 Element Plus 名称字符串**（`DataBoard`/`Cpu` 等），需用 `<component :is>` 动态渲染。
5. **动效要克制**：现有规范 160/240/320ms，只动 transform/opacity，且必须有 `prefers-reduced-motion` 降级。
6. **移动端**：≤768px 侧栏需折叠成图标栏，主看板卡片单列堆叠（现有实现可参考）。
7. **表格列不要砍**：每列表头都对应真实字段，删了会影响运维操作。
