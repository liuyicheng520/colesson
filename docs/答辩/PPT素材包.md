## 第 1 页 · 项目痛点

**大标题**：三个断点，让"个性化学习"停在了口号

**正文要点**
- 备课要跨 4 个工具：PPT → 讲稿 → 音频 → 平台，同一份内容搬 4 次
- "个性化"只有一个下拉框：年级/班级标签，无画像、无差异
- 学情只剩一个数字：完成率 78%，看不到谁卡在哪个知识点
- 三个断点互相叠加：备课慢 → 内容旧 → 无个性化 → 无数据 → 更没动力改课
- 我们的切入点不是"加功能"，是把断点接上

**配图建议**：左侧三张"断开的链条"示意（备课/画像/学情），右侧一条闭合环（画像→资源→路径→学习→数据→回到画像）

**讲稿（≤100 字）**
> 在线教学平台不缺功能，缺闭环。老师备课要跨四个工具；学生的"个性化"只有一个下拉框；老师看到的学情只剩完成率。三个断点连起来，就是我们现在要解决的问题。

**评委高频风险**
- "访谈了几位老师？有数据吗？" → 需准备 ≥5 位一线教师访谈/问卷
- "这些问题所有平台都有" → 回答必须落在"闭环"而非单点

**正文要点**

- 我们的定位：面向高校·职校**单班教学**的 AI 教学闭环主机
- 一套部署、三端协同、数据留校内

**配图建议**：三线并行时间轴（政策/技术/产业）汇聚到一个箭头，指向"单班闭环主机"

**讲稿（≤100 字）**
> 政策要求落地、技术成本下降、现有产品要么智能化浅、要么只做单点工具。三线交汇的位置，正好是"把智能嵌进教学过程"的产品，我们做的是单班场景的闭环主机。

## 第 3 页 · 研发初衷

**大标题**：从"功能齐全"到"确实能用，且不夸大"

**正文要点**
- 第一版按功能清单开发：画像、资源、路径、答疑、班级、作业、签到、公告、学情
- 跑通后发现两个真问题
- 问题一：功能齐全 ≠ 能用 —— 自查出 22 条功能 / 19 条界面 / 8 条安全问题
  - 典型：看板做得漂亮，但驱动它的埋点**从未被调用**，图表永远是 0
- 问题二：AI 必须诚实 —— 未配密钥时走模板生成，早期没有标注，老师会误当 AI 产出
- 定下的原则：**能力不足可以接受，伪装能力不可接受**
- 结果：所有 AI 输出带来源标记（`ai` / `local_template`）

**配图建议**：左侧"功能清单打勾"截图，右侧"问题清单表"截图（可打码），中间箭头写"审计驱动迭代"

**讲稿（≤100 字）**
> 我们先把功能做齐，然后做了一轮自查：22 条功能问题、19 条界面问题、8 条安全问题。最典型的是看板很美但埋点从未被调用。由此定下原则：能力不足可以接受，伪装能力不可接受。

**评委高频风险**
- "自曝这么多问题，是不是半成品？" → 话术转向"发现—修复—回归"三件套
- "所以没真正接大模型？" → 架构按真实 API 设计，附 provider 配置截图

## 第 4 页 · 核心技术（架构）

**大标题**：一宿主 + 一智能体层 + 三端前端

**正文要点**
- 宿主层：Spring Boot 2.7 / Java 17 —— 认证、班级、作业、项目、反代
- 智能体层：FastAPI —— 画像、资源编排、路径、答疑、行为分析
- 前端：Vue 3 + TS + Element Plus（教师端多页、学生/管理端 SPA）
- 部署：**单 JAR，对公网只开 8082**，内部反代 8000，学生端后端随宿主自动拉起
- 规模：34 个 Java 类 / 82 个 Vue 组件 / 130 个 Python 模块
- 为什么双栈：Java 负责稳定事务与权限，Python 负责模型生态与并发编排

**配图建议**：三横条架构图（浏览器三端 → 8082 宿主 → 8000 智能体层 → 向量库/LLM）

**讲稿（≤100 字）**
> 架构一句话：一个宿主、一个智能体层、三端前端，打包成一个 JAR。对公网只开 8082，学生端后端随宿主自动拉起。Java 管事务与权限，Python 管模型与编排。

**评委高频风险**
- "为什么双栈？不能说团队熟悉" → 用职责分工回答，并主动说代价（内存占用、跨语言鉴权）
- "2 核 1.6G 服务器扛得住吗？" → 定位单班试点，给出实测内存占用

## 第 5 页 · 核心技术（多智能体）

**大标题**：唯一真编排：8 个专职 Agent + 真实进度

**正文要点**
- 8 个专职 Agent：Coordinator / LearningAnalysis / Document / Question / Mindmap / Extension / Animation / Validator
- 固定流水线：总协调 → 学情分析 → 5 个并行生成 → 校验
- 四阶段落库：`parse → plan → generate → validate`，前端 SSE 逐个消费
- **学生看到的每一步都对应后端真实执行**，不是定时器模拟
- 失败可定位到具体阶段，不是笼统"生成失败"
- 诚实边界：备课讲稿 / 路径规划 / 答疑是**单次调用 + 模板兜底**，不打包成"多智能体"

**配图建议**：编排器执行流程图 + SSE 事件流截图（带阶段名与时间戳）

**讲稿（≤100 字）**
> 资源生成是真编排：8 个专职 Agent，四阶段落库，前端通过 SSE 消费真实进度。学生看到的每一步都能对上后端。我们也要说清楚：备课、路径、答疑是单次调用，不包装成多智能体。

**评委高频风险**
- **最大风险**："你说多智能体，备课是吗？" → 必须主动澄清，装处处多智能体一定被问穿
- "Agent 之间怎么协商的？" → 如实说：固定流水线，不是自治协商

## 第 6 页 · 核心技术（RAG 双通道）★答辩强项

**大标题**：先查本地知识库，再让模型开口

**正文要点**
- 向量库：ChromaDB 持久化，按文件签名**增量重建**，只重算变更文件
- 嵌入三级降级：Qwen 向量 API → 本地 fastembed（bge-small-zh）→ 哈希向量兜底
- 答疑通道：检索本地库 + 联网检索 + 画像适配，回答带**可点开的文档引用**（文件名 / 页码 / 片段）
- 资源通道：生成前按主题检索，注入 `ctx.kb_context`，5 个生成 Agent prompt 均有「知识库参考」
- 实测索引：27 个文件 / **2389 个文本块**（网络 RFC、数据结构、数据库、Java、操作系统）
- 实测性能：检索 **0.096 秒**（命中 6 条，top-1 来源正确）
- 诚实边界：当前离线环境模型下载失败 → 走哈希向量，语义能力弱于 bge

**配图建议**：检索链路图（问题 → 向量库 top-k → 注入 prompt → 带引用回答）+ 真实引用截图

**讲稿（≤100 字）**
> 学生端的答疑和资源生成都不是裸调模型。先检索本地向量库，命中片段注入 prompt，回答会带文档引用，能点开原文。索引 2389 个文本块，检索 0.1 秒。离线环境我们退到哈希向量，语义会弱一些，但不中断。

**评委高频风险**
- "用的是 bge 还是哈希？中文能查英文吗？" → 如实答：当前哈希兜底，跨语言排序会退化
- "知识库能覆盖我的课程吗？" → 27 文件、五方向，扩充路径是教师上传即入库

## 第 7 页 · 核心技术（画像 + 数据闭环）

**大标题**：画像不是展示页，是可开关的系统行为

**正文要点**
- 画像四模式采集：对话 / 问卷 / 测评 / 手动 → 融合为六维画像
- 下游三处真实消费：资源生成调节语气难度、路径规划裁剪节点、答疑调整提示层级
- 可现场验证：勾选「本次忽略画像」→ 生成结果可见差异（不是口号）
- 学情闭环：会话时长 + 节点进度 + 行为事件三源合一
- 曾经"永远为 0"的看板，现已显示真实时长与趋势
- 无作答数据时"平均正确率"显示「—」，不用完成率冒充

**配图建议**：左画像六维雷达截图，右"忽略画像"开关前后的生成结果对比

**讲稿（≤100 字）**
> 画像是四模式采集成六维，然后真的被三处消费：资源、路径、答疑。现场可勾掉画像开关看差异。学情我们补了三源数据，看板从永远 0 变成真实值；没有作答数据就显示"—"，不编。

**评委高频风险**
- "画像数据哪来的？准吗？" → 说明四模式与融合逻辑，不承诺准确率
- "知识点掌握度是真的吗？" → 如实：部分由状态映射，非真实测评

## 第 8 页 · 成果验收

**大标题**：三端主流程可走通，数据是真的

**正文要点**

- 管理员：登录 → 数据大盘 → 用户管理 → 菜单配置（全通，列表不返密码哈希）
- 质量证据：功能 22 条 / 界面 19 条 / 安全 8 条问题清单，逐条状态 + 复现步骤
- 安全加固 20+ 项已回归：桥接共享密钥、判题 fail-closed、附件白名单、限流、改密全局撤销会话、CDN 全量本地化
- 全端回归：43 页状态码全绿 + 6 条核心接口链路；三端 31 页 375px 真实视口实测横向溢出 0
- 真实评测：解析基准 101 份课件成功率 100%（P50 158ms）；问答评测数据集命中率 100%
- 功能闭环补全：智能体配置真实保存（管理员+校验）、实战演练自测闭环（作答/对照/自评/持久化）
- 主动列剩余项：知识点掌握度为画像推算非实测、习题自动判分以自评代替（教师批改走作业系统）

**配图建议**：三端流程图 + 4 宫格截图（教师发布、学生答疑引用、数据看板、管理端大盘）

**讲稿（≤100 字）**
> 验收口径不是能演示，是三端主流程都走通、数据是真的。教师从 PPT 到发班全通，学生答疑能看到引用原文。质量上：43 页回归全绿、31 页 375px 实测零溢出、解析基准 101 份课件成功率 100%。没做好的我们也列出来：掌握度是推算值，不是实测。

**评委高频风险**
- **最致命**："你这儿全是 0，跑通过吗？" → 答辩前必须预置演示数据
- "假按钮" → 隐藏或置灰未实现入口
- "只有 4 个用户，能支撑一个班吗？" → 定位单班试点，不吹大规模

## 第 9 页 · 商业模式

**大标题**：私有化部署 + 按班订阅，AI 成本可分段

**正文要点**
- 主收入：校级私有化部署（一次性部署费 + 年度维护）
- 次收入：按"活跃班级数"订阅（比按人头更易过预算）
- 远期：校本内容资产共享（跨校需另设计授权与分成）
- 成本结构：AI 调用是主要变动成本
- 关键设计：无密钥时以本地模板运行 → 学校可**零成本先试点**，再放开 AI 额度
- 推广路径：单院系试点（1 师 + 1 班 + 1 课）→ 用一学期学情与备课工时说话 → 院系立项 → 校级

**配图建议**：三层收入漏斗 + "试点→立项→推广"阶梯图

**讲稿（≤100 字）**
> 商业模式是私有化部署加按班订阅。关键设计是没有 AI 密钥也能跑——学校零成本试点，用一学期的备课工时和学情决定是否续费，而不是靠功能清单说服采购。

**评委高频风险**
- "采购流程半年，你怎么活？" → 零成本试点 + 院系立项阶梯
- "凭什么收费？" → 给出成本—定价算式，哪怕估算
- "有学校在用吗？" → 没有就说"试点洽谈中"，绝不虚构客户

## 第 10 页 · 社会影响

**大标题**：把备课能力、学情可见度、数据主权还给学校

**正文要点**
- 缩小校际备课能力差距：从 PPT 到可发布智课，一次上传
- 教师减负：机械劳动（整理讲稿、拆章节、出练习）自动化，精力回到设计与答疑
- 数据主权：私有化部署，学生画像/行为/作答不出校门
- 让"因材施教"可被检查：画像可开关、结果可对比
- 立场：**AI 出初稿，教师做终审**；系统保留来源标记，老师始终知道哪段是机器生成
- 不承诺提分，只承诺可测量项：备课耗时、内容覆盖、学情可见度

**配图建议**：四象限（公平/减负/主权/可验证）+ "AI 初稿 → 教师终审"流程

**讲稿（≤100 字）**
> 社会价值我们不喊口号：让薄弱校新教师有同等质量的备课起点、把重复劳动自动化、让数据留在校内。立场很清楚——AI 出初稿，教师做终审，来源标记永远可见。我们不做提分承诺。

**评委高频风险**
- "这些话谁说都行" → 每条价值都要绑一个可演示行为或可测指标
- "AI 会让教师更依赖" → 用"来源标记 + 教师终审"回答
- "合规吗？" → 本地化 + 权限隔离，承认未做等保测评

## 第 13 页 · 竞品对比
