## 一、项目痛点

### PPT 文稿

在线教学平台并不缺功能，缺的是**把功能串成一条闭环**。我们在真实课堂里观察到三个反复出现的断点：

**痛点一：备课是四次重复劳动。** 一位老师准备一节新课，通常要在 PPT、讲稿、音频工具、课程平台之间来回搬运同一份内容。我们的备课台把这条链路压成一条流水线：上传 PPT → 解析结构 → 生成讲稿 → 生成讲解视频 → 选班发布。系统实测一次完整发布涉及 4 个步骤、1 个入口，不再需要跨工具复制粘贴。

**痛点二："个性化"停在标签上。** 多数平台的"因材施教"是一个年级下拉框。学生的真实差异（知识基础、学习风格、目标诉求）没有被采集，更没有被下游使用——推荐资源靠热门排序，路径规划靠统一模板。

**痛点三：学情数据不回流。** 学生学完了，老师看到的是"完成率 78%"这样的单一数字，看不到哪个知识点卡住了人、哪道题错得集中。教与学的下一次迭代缺乏输入。

这三个断点彼此叠加：备课成本高 → 内容更新慢 → 学生个性化无内容可依 → 学情无数据可析 → 老师更没动力改课。

### 创新点锚定

本项目的切入点不是"再加一个功能"，而是**把断点接上**：一边是教师的"备课—发布—学情"，一边是学生的"画像—资源—路径—学习—答疑—数据"，两端在同一个班级空间里交换数据。

### 评委视角：风险与追问

| 风险 | 具体会被怎么问 | 建议准备 |
|---|---|---|
| 痛点缺少外部证据 | "你说老师要跨四个工具，有数据吗？访谈了几位老师？" | **必须补**：≥5 位一线教师的访谈记录或问卷（哪怕小样本），否则痛点=主观断言 |
| 痛点与方案对不上 | "第三条痛点说学情不回流，但你们的学生端看板是最近才修好的？" | 承认演进过程，用"我们发现问题→重构数据链路"的迭代叙事回应，不要假装一开始就完备 |
| 痛点过于通用 | "这些问题所有平台都有，你的特殊性在哪？" | 强调**闭环**而非单点：竞品普遍强在单环节（如题库、如直播），弱在端到端 |

## 二、项目背景

### PPT 文稿

**政策面**：教育数字化已成为国家层面的长期方向，"人工智能+教育"从试点走向常态应用。政策红利带来的不是预算宽松，而是**对"可落地、可验收"的产品要求变高**——学校采购越来越看"能不能在现有班级结构里跑起来"，而不是看概念演示。

**技术面**：三个条件同时成熟，使"AI 参与完整教学闭环"第一次具备工程可行性：
1. 大模型推理成本降到学校可承受区间；
2. 多模态生成（文档、习题、思维导图、讲解视频）具备可用质量；
3. 开源前端/后端栈足以在低配服务器上跑完整平台。

**产业面**：现有产品大致分三类——通用 LMS（功能全但智能化浅）、AI 工具集（单点强但不成体系）、题库/直播平台（场景窄）。**缺的是把"智能"嵌进教学过程而不是贴在过程旁边**的产品。

### 创新点锚定

项目定位：**面向高校/职校单班教学场景的"AI 教学闭环主机"**——一套部署、三端协同、数据留在校内。

### 评委视角：风险与追问

| 风险 | 具体会被怎么问 | 建议准备 |
|---|---|---|
| 引用政策空泛 | "具体哪个文件？哪条要求？" | 若无法准确引用，**不要在 PPT 写文号**，改写成"教育数字化方向下，学校对……的要求提升"，避免被抓硬伤 |
| 竞品分析缺失 | "和超星、雨课堂、智慧树比，你的差异是什么？" | 准备一页竞品对比表（功能维度：备课生成/个性化/学情回流/私有化部署），只写你能验证的差异 |
| "成本可承受"未量化 | "一次生成成本多少？" | 补真实的 token 成本测算（若未接真实 API，明确说"当前为 Mock，成本模型见附录"，不要编数字） |

## 三、研发初衷

### PPT 文稿

这个项目起点很朴素：**我们先做功能，然后被迫做取舍。**

第一版我们按"功能清单"开发——画像、资源、路径、答疑、班级、作业、签到、公告、学情，一个不落。跑通之后发现了两个真问题：

**第一，功能齐全不等于能用。** 我们做了一轮全面自查，列出 22 条功能问题、19 条界面问题、8 条安全问题。其中最有代表性的一条：学习数据看板做得很漂亮，但驱动它的行为埋点**从未被任何页面调用**——图表永远是 0。这不是"少写一行代码"，而是"我们以为做了，其实没通"。

**第二，AI 能力必须诚实。** 未配置大模型密钥时，系统会走本地模板生成内容。早期版本没有标注，老师会把模板稿当成 AI 产出。我们后来强制在接口返回 `source: local_template` 并在界面上加"演示模式"水印——**能力不足可以接受，伪装能力不可接受**。

所以研发初衷可以浓缩为一句话：**把"看起来能做"变成"确实能用、且不夸大"**。这条原则直接决定了后面的技术取舍（见第四章）与验收标准（见第五章）。

### 创新点锚定

研发方法本身构成一项"工程创新"：**以审计驱动的迭代**——把功能、界面、安全、动效四条线分别建立可复现的问题清单，逐条修复并回归验证，而不是靠"演示时别点那里"。

### 评委视角：风险与追问

| 风险 | 具体会被怎么问 | 建议准备 |
|---|---|---|
| 自曝问题可能反噬 | "你自己说 22 条功能问题，那产品是不是半成品？" | 话术要转向：**问题清单 + 已修复比例 + 回归证据**三件套，展示"我们发现并解决了"的能力，而不是罗列缺陷 |
| 「诚实地用模板」被误解为能力弱 | "所以你们没有真正接入大模型？" | 明确区分：架构已按真实 API 设计（多 provider + 降级），当前环境用 Mock 是为了可复现演示；附一张 provider 配置截图 |
| 初衷叙事比重过大 | PPT 前 3 页都在讲心路历程 | 压缩到 1 页，把篇幅留给核心技术与验收 |

## 四、核心技术

### PPT 文稿

**总体架构：一宿主 + 一智能体层 + 三端 SPA。**

- **宿主层**：Spring Boot 2.7（Java 17）负责认证、班级、作业、项目、静态资源与反向代理；
- **智能体层**：FastAPI（Python）承载画像、资源生成、学习路径、答疑、行为分析；
- **前端**：Vue 3 + TypeScript + Element Plus，教师端为多页应用、学生/管理端为单页应用；
- **部署形态**：单端口 8082 对外，内部反代到 8000，学生端后端随宿主自动拉起——**一套 JAR 即可交付**，这对学校私有化部署是关键约束。

规模：34 个 Java 类、82 个 Vue 组件、130 个 Python 模块。

**技术要点一：真正的多智能体编排（本项目唯一完整兑现的"多智能体"）。**

资源生成采用「总协调 → 学情分析 → 5 个专职智能体并行 → 校验」的固定流水线，共 8 个专职 Agent（Coordinator / LearningAnalysis / Document / Question / Mindmap / Extension / Animation / Validator）。关键在**进度是真的**：编排器写入 `parse → plan → generate → validate` 四个阶段，前端通过 SSE 逐个消费，学生看到的每一步都对应后端的真实执行，而不是定时器模拟。

> 必须如实说明：备课讲稿、路径规划、答疑三处目前是**单次模型调用 + 模板兜底**，不是多智能体协作。我们在答辩中会主动区分，不把四处都包装成"多智能体"。

**技术要点二（新增·答辩强项）：本地向量知识库 + 大模型的 RAG 双通道。**

学生端的两条核心能力都不是"直接问模型"，而是**先检索本地语料、再让模型基于语料作答**：

- **知识库层**：ChromaDB 持久化向量库（collection `cs_knowledge_base`），支持增量重建（按文件签名比对，只重建变更文件）；
- **向量层**：三级降级——Qwen 向量 API → 本地 fastembed（BAAI/bge-small-zh-v1.5）→ 哈希向量兜底，离线环境也能检索；
- **答疑通道**：先检索本地知识库，再叠加联网检索与画像适配，回答时返回**可点击的文档引用**（`doc_citations`，含文件名、页码、原文片段）；
- **资源生成通道**：编排器在生成前按主题检索知识库，把命中片段注入 `ctx.kb_context`，5 个生成智能体的 prompt 中都有「知识库参考」段落——**生成的讲义有本地出处，不是凭空编**。

当前索引实测：27 个文件 / 2389 个文本块（计算机网络 RFC、数据结构、数据库、Java、操作系统五大方向）。

> 必须如实说明两点：① 本机离线导致 fastembed 模型无法下载，当前走的是哈希向量兜底（检索可用，但语义能力弱于 bge 模型）；② 中文提问检索英文语料时排序会退化，跨语言检索需接入真正的多语种向量模型。

**技术要点三：画像驱动下游，而不是画像孤立存在。**

画像支持四种采集模式（对话 / 问卷 / 测评 / 手动），融合后写入六维画像；下游三处真实消费：资源生成按画像调整语气与难度、路径规划按画像裁剪节点、答疑按画像调整提示层级（hint 分级）。**画像不完整时系统不阻塞**，而是显式提示"将使用默认策略生成"。

**技术要点四：学情回流链路（从"没有数据"到"真实数据"）。**

我们补齐了行为事件生产者：学生进入学习页开启会话，完成节点时回传真实学习时长（上限 4 小时防挂机），退出时结束会话。看板的"累计时长/趋势"由此变为真实值；无作答数据时"平均正确率"显示"—"而不再用路径完成率冒充。

**技术要点五：AI 降级可识别。**

所有 AI 输出带来源标记；未配密钥时返回 `local_template` 并在界面提示。问答通道明确告知"已切换本地模式"。

**技术要点六：安全底线（竞赛项目最容易翻车的地方）。**

判题沙箱仅允许在 macOS sandbox-exec 隔离下执行学生代码，其他平台**默认拒绝**而不是裸跑；宿主与学生端之间用共享密钥桥接，禁用无鉴权账号同步；登录失败锁定、匿名接口限频、附件扩展名白名单、上传图片魔数校验。这些不是加分项，而是"敢上线"的前提。

### 创新点（三类）

**A. 技术创新**

| 创新点 | 传统做法 | 本项目做法 | 可验证价值 |
|---|---|---|---|
| 编排进度真实可观测 | 前端定时器模拟"AI 正在思考" | 编排器落库 4 阶段，SSE 推送真实阶段 | 学生/教师看到的每一步可追溯；失败时能定位到具体阶段 |
| 本地向量知识库 RAG 双通道 | 直接调用大模型，答案无出处 | 检索本地语料 → 注入 prompt → 回答带文档引用（文件名+页码+片段） | 答疑可点开引用原文；讲义生成有本地出处 |
| 向量层三级降级 | 依赖单一向量 API，离线不可用 | Qwen API → 本地 bge → 哈希兜底 | 断网环境检索仍可用（能力降级但功能不中断） |
| 画像→下游三处消费 | 画像作为展示页 | 资源/路径/答疑三处读取画像参数 | 关闭画像开关后生成结果可见差异（可现场演示） |
| 学情闭环可量化 | 只有完成率 | 会话时长 + 节点进度 + 行为事件三源合一 | 看板数据从"永远 0"变为真实值 |
| 降级可识别 | 失败即报错或静默返回模板 | 返回来源标记 + 界面水印 | 老师不会误把模板当 AI 成果 |

**B. 应用创新**

| 创新点 | 说明 | 对比价值 |
|---|---|---|
| 备课一次成型 | PPT 解析→讲稿→讲解视频→选班发布，单入口 4 步 | 传统流程需跨 3–4 个工具 |
| 班级空间聚合 13 个教学动作 | 概览/名单/课程/发布/作业/资料/签到/公告/学情/助教/精选/设置等 | 教师不必在多个系统间切换 |
| 作业全链路闭环 | 布置→提交→批改→精选→学情 | 多数 AI 工具止于"生成"，不覆盖"收作业与批改" |
| 学生端按学习节奏排序 | 首页→画像→资源→路径→课程→答疑→数据 | 导航顺序即学习闭环顺序，降低迷路成本 |

**C. 模式创新**

| 创新点 | 说明 | 对比价值 |
|---|---|---|
| 单 JAR 私有化交付 | 宿主+智能体层+三端前端打包为一份可执行 JAR，数据留校内 | 云 SaaS 方案难以满足数据不出校 |
| 教师内容资产可复用 | 备课产物绑定多个班级复用 | 一次备课多班使用，边际成本递减 |
| 双轨存储自适应 | MySQL 可用则入库，不可用回退 JSON | 低配环境也能跑起来（同时是风险点，见下） |

### 评委视角：风险与追问

| 风险 | 具体会被怎么问 | 建议准备 |
|---|---|---|
| **"多智能体"名不副实（最大风险）** | "你说多智能体，具体哪几个 Agent 协作了？备课是吗？" | **主动提前澄清**：只有资源生成是真编排；其余是单调用。准备编排器源码截图 + SSE 事件流录屏。装作处处多智能体一定被问穿 |
| 架构分层理由不足 | "为什么 Java + Python 双栈？不能说因为团队熟悉。" | 给工程理由：Java 侧负责稳定事务与文件/权限，Python 侧负责模型生态与并发编排；并说明代价（多进程、内存占用、跨语言鉴权） |
| 双栈带来的运维复杂度 | "一台 2 核 1.6G 的服务器扛得住吗？" | 给出实测：宿主 + 智能体层常驻内存占用（需现场补测），以及"单班规模"的定位边界 |
| **RAG 语义能力被质疑** | "你的检索用的是 bge 还是哈希？中文提问能查到英文文档吗？" | 诚实说明：当前离线下用哈希兜底，语义弱；中文查英文语料排序会退化。**不要声称"语义检索已达到生产水平"** |
| 知识库语料单薄 | "你的知识库有多少东西？能覆盖我的课程吗？" | 实测 27 文件 / 2389 块，仅计算机五大方向；给出扩充路径（教师上传教材/讲义即入库） |
| 判题沙箱在 Linux 不可用 | "学校服务器是 Linux，判题还能用吗？" | 诚实回答：当前仅 macOS 可用，Linux 需容器化，列为下一步 |
| 双存储隐患 | "JSON 和 MySQL 同时存在，切换后数据会丢吗？" | 这确实是未解决问题，答辩前要么统一存储，要么准备好说明（我们已实测到旧数据在切换后不可见） |

## 五、成果验收

### PPT 文稿

**验收口径：不是"能演示"，而是"三端主流程可走通、数据真实、异常有反馈"。**

已完成的三条主流程（均实机验证）：

| 角色 | 流程 | 结果 |
|---|---|---|
| 教师 | 登录 → 上传 PPT → 解析 → 生成讲稿 → 建项目 → 发布 → 绑班 → 发给本班 → 查看学情 | 全通；讲稿降级时返回 `source: local_template` 并明确提示 |
| 学生 | 登录 → 邀请码入班 → 查看本班智课 → 学习 → 答疑（流式）→ 查看学习数据 | 全通；看板显示真实学习时长与趋势 |
| 管理员 | 登录 → 数据大盘 → 用户管理 → 菜单配置 | 全通；用户列表不返回密码哈希与手机号 |

**质量验收证据（可放进附录）：**
- 功能问题清单 22 条、界面问题清单 19 条、安全问题清单 8 条，逐条标注状态与复现步骤；
- 已修复项的回归记录：安全加固 20 项（含桥接鉴权、判题 fail-closed、附件白名单、限流、登录锁定），全部复测通过；
- 界面截图集 59 张（三端 × 桌面/移动 × 默认/弹窗/空态/错误态）；
- 动效规范与实现：统一令牌（160/240/320ms），全部动效只动 transform/opacity，并提供 reduced-motion 降级。

**尚未闭环（如实列出）：**
1. 学习数据中"知识点掌握度"仍由状态映射得出，非真实测评；
2. 资源内习题采用"作答草稿 + 参考答案自评"模式（自动判分未做，教师批改走作业系统）。

**本轮已闭环（原清单项）：**
- ~~习题资源不能作答~~ → 实战演练自测闭环（作答草稿持久化、对照参考答案、自评、进度）；
- ~~智能体配置"保存"为演示态~~ → 后端真实更新接口（管理员权限 + 字段校验），端到端验证通过；
- ~~运营看板数据文件缺失~~ → 真实评测报告入库（解析基准 101 样本、问答评测 20 样本），页面恢复可用。

| 风险 | 具体会被怎么问 | 建议准备 |
|---|---|---|
| **演示数据为空**（最致命） | "你这儿全是 0，是不是没跑通过？" | 答辩前预置演示数据：1 个班、2 门智课、3 名学生、作业与提交记录；并截图存档 |

## 六、商业模式

### PPT 文稿

**定位：面向院校的私有化部署 + 按班订阅。**

三类收入：

1. **校级部署授权（主）**：一次性部署费 + 年度维护费。卖点是数据不出校、单机可跑、与现有班级结构兼容。
2. **按班订阅（次）**：以"活跃班级数"计费，学校可按学期增购。对采购方而言比"按人头"更容易过预算。
3. **内容资产增值（远期）**：优质备课产物可在校内共享复用，形成校本资源库；跨校共享需另行设计授权与分成。

**成本结构**：AI 调用是主要变动成本。系统已做"降级可识别"，无密钥时以本地模板运行——这既是演示保障，也让学校可以先零成本试点、再逐步放开 AI 额度。

**推广路径**：以单院系/单专业为最小单元试点（1 位教师 + 1 个班 + 1 门课），用一学期的学情数据与备课工时节省作为续费依据，而非用功能清单说服采购。

### 创新点锚定

商业模式创新点在于**把"AI 成本"变成可分段购买的额度**，而不是打包成不可控的年费；同时用"单机可跑"降低学校 IT 部门的接入阻力。

### 评委视角：风险与追问

| 风险 | 具体会被怎么问 | 建议准备 |
|---|---|---|
| 教育客户采购周期长 | "学校一个采购流程半年，你怎么活？" | 给出"免费试点班 → 院系立项 → 校级推广"的阶梯，并把试点成本压到接近零（这是本地模板降级的真实价值） |
| 定价无依据 | "一个班一年多少钱？凭什么？" | 至少给一个成本—定价模型：AI 调用成本 + 运维 + 毛利，哪怕估算也要有算式 |
| 与免费/低价竞品冲突 | "学校为什么要为你付费，而不是用免费的？" | 差异化三句话：闭环（不只生成）、私有化（数据不出校）、可验收（问题清单+回归证据） |
| 无真实客户 | "有学校在用吗？" | 若没有，明确说"处于试点洽谈阶段"，不要虚构客户名称 |

## 七、社会影响

### PPT 文稿

**第一，缩小"备课能力"的校际差距。** 优质讲稿与课程结构长期集中在少数教师手里。系统把"从 PPT 到可发布智课"的门槛降到一次上传，薄弱校的新教师可以借用同等质量的备课起点。

**第二，把教师从重复劳动中释放。** 备课环节的机械劳动（整理讲稿、拆分章节、生成配套练习）被自动化，教师精力回到设计与答疑。

**第三，学习数据留在校内。** 私有化部署意味着学生的画像、行为、作答数据不出校门，这对未成年人/在校学生的数据保护是实质差异，而非口号。

**第四，让"因材施教"可被检查。** 画像驱动下游三处消费，意味着"个性化"不再是宣传语，而是可开关、可对比的系统行为（关闭画像生成的结果可见差异）。

### 评委视角：风险与追问

| 风险 | 具体会被怎么问 | 建议准备 |
|---|---|---|
| 社会价值空泛 | "这些话说给谁听都行。" | 每条社会价值绑定一个可演示的系统行为或一个可测量的指标（备课工时、班级覆盖数） |
| 教育公平议题被反向质疑 | "AI 生成内容会不会让教师更依赖，反而拉低教学质量？" | 准备立场：AI 出初稿、教师做终审；系统保留"source"标记，教师始终知道哪段是机器生成 |
| 数据伦理 | "学生画像涉及敏感信息，合规吗？" | 说明数据本地化 + 权限隔离 + 不对外共享；承认尚未做等保测评 |
| 过度承诺 | "能提升多少成绩？" | **绝不承诺提分**。只承诺可测量项：备课耗时、内容覆盖、学情可见度 |
